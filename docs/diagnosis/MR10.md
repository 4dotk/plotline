# Diagnosis: MR10 (BHK partition: Σ per-BHK counts = source count)

**Class: ill-conceived MR when L2 fires (each run widens its own soft filters). No agent fault.** With the loops off, the partition holds on all 350 bases.

## Why MR10 was picked

0 conditioned violations out of 154 evaluated. The unconditioned rate is **108/350 = 30.9 %** (`results/headline_table.md`), the second highest.

## Evidence (T56)

**1. Diff bases by skip reason** (`results/violations_unconditioned.csv`): all 108 bases are `L2_attempts > 0 + soft filter set (price_band)`. Every diff (2,739 rows) is a `listing_count`.

**2. Loops on vs off** (`uv run python -m tests.mt.diagnose --mr MR10` → `results/diagnosis/MR10_loops.csv`):

```
MR10: 350 bases; 108 with diffs (loops on); 0 of those still differ with loops off;
      108 of 108 have different soft filters in effective_criteria
```

With the loops off, the 196 skipped bases are still skipped, because the soft-filter skip does not depend on the loops. But **all 350 bases have 0 diffs**, including those 196.

**3. Minimal case: base 321** (Anna Nagar, window to 2014-06, price band ₹12.40M–18.30M, 44 rows; `results/diagnosis/MR10_base321_trace.txt`):

| Run | L2 path | Final `price_band` | Rows |
|---|---|---|---|
| Source (all BHK) | 4/12 → 8/12 → 9/12, coverage met after attempt 2 | [9451885, 21249345] | 73 |
| `bhk=[1]` | 1/12 → 2/12 → 5/12, dropped (attempt 3) | none | 54 |
| `bhk=[2]` | 1/12 → 1/12 → 1/12, dropped (attempt 3) | none | 26 |
| `bhk=[3]`, `bhk=[4]` | 0/12 throughout, dropped | none | 0, 0 |

Each per-BHK slice is thinner than the whole, so it widens further. In this case all four drop the band, and Σ = 54 + 26 = **80 ≠ 73**.

## Oracle and hand check (T57)

* **Oracle**: 0 mismatches in the source and in all four follow-ups of base 321 (`oracle_mismatches=0` in the trace file).
* **Hand check** in plain pandas (Anna Nagar, the 12 months to 2014-06, `lo ≤ price ≤ hi`):
  * the source band [9451885, 21249345] gives **73** rows, as in the report;
  * per BHK, with no band: {1: 54, 2: 26, 3: 0, 4: 0}, sum **80**, as in the follow-ups;
  * per BHK, with the **source's** band held fixed: {1: 53, 2: 20, 3: 0, 4: 0}, sum **73**. The partition is exact when every run answers the same query.

## Classification

**Ill-conceived MR under L2.** The relation assumes every run filters with the same soft criteria. L2 is designed to widen each query by its own coverage (D7, `GLOBAL_CONTRACT.md` §7.3), so a thinner BHK slice legitimately ends with a wider (or no) band. The skip rule (`L2_attempts > 0` or any soft filter set) is correct.

**Note for the report:** the rule also skips the 196 soft-filter bases when the loops are off, although they then show 0 diffs. A loops-off variant of MR10 would test the partition on those bases (e.g. `price_band`-boundary defects) without the L2 confound. It is not run in the headline table; recorded as a possible extension.
